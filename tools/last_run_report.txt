KURZBEFUND
Jeder WebFetch auf eine Shop-Seite wird sofort vom Werkzeug selbst abgelehnt,
bevor die Seite überhaupt angefragt wird:
  error_type "PROVENANCE_REQUIRED": "URL not in provenance set. web_fetch can only
  retrieve URLs that appeared in a user message, a prior web_fetch result, or an
  approved fetch prompt."
Die Shop-URLs stehen nur in tools/daily_update.md (Dateiinhalt), nicht in der
Nachricht des geplanten Tasks. Deshalb darf WebFetch sie nicht laden -> 0 Releases
gesehen -> "0 new releases". Die Shops selbst blockieren NICHT; die Seiten wurden
gar nicht abgerufen.

VORSCHLAG ZUR BEHEBUNG
Alle Shop-Listen-URLs aus Abschnitt 4 von tools/daily_update.md wörtlich in den
Prompt des geplanten Tasks kopieren (z.B. als Liste am Ende). Dann gelten sie als
"in a user message" und WebFetch darf sie laden. Produktseiten-Links, die aus einem
WebFetch-Ergebnis stammen, sind danach automatisch erlaubt.
Hinweis: Auch Seiten wie ?page=2, /page_2, Clone-Tag-Listen und die einzelnen
Juno-Subgenre-Seiten müssen einzeln im Prompt stehen.
